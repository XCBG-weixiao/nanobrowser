# 白名单自动审批使用说明

本功能由 Nanobrowser 插件和改造后的 dbgpt 后端共同提供。固定审批流程不调用模型，对话管理使用你配置的模型。

后端改造见 [集成补丁与应用步骤](../integrations/dbgpt/README.zh-CN.md)。

## 启动与配置

1. 在 dbgpt 项目按 PROJECT.md 启动后端和前端。后端自动恢复已启用的任务，不需要另外启动 Agent 服务。
2. 插件使用 Node 24.22.1+、pnpm 10.34.7。执行 `pnpm install --frozen-lockfile`，再执行 `VITE_POSTHOG_API_KEY= VITE_POSTHOG_HOST= pnpm build`。离线安装使用 `pnpm install --offline --frozen-lockfile --store-dir <离线store路径>`。
3. 打开 `chrome://extensions`，启用开发者模式，加载构建后的 `dist/`。已打包产物直接解压并加载其中的 `dist/`。
4. 打开插件设置 → **平台与自动审批**，或侧栏顶部 **白名单审批**。
5. 本机测试：允许的平台网址填写 `http://127.0.0.1:3001/`，平台后端地址填写 `http://127.0.0.1:5670`。保存范围后，使用平台管理员账号登录。
6. 点击 **启用：已有和新增全部通过**，允许 Chrome 桌面通知权限。任务状态、待审批数量、累计自动通过数量、最近检查与结果均在此显示。

服务器每 30 秒查询全部待审批记录，每轮最多 100 条，积压在后续轮次继续处理。首次启用处理存量，之后处理新增。点击 **暂停自动审批** 阻止下一轮写入；已提交事务保留实际结果。

## 页面范围

- `/` 允许同协议、同主机和同端口的所有路径；`/construct` 允许该路径及其子路径，不允许 `/construction`。
- `localhost`、`127.0.0.1`、不同端口、不同协议分别匹配，不允许其他域名或子域名。
- 页面读取、截图、点击、输入、导航、标签页和 iframe 均受范围限制，模型没有更改范围的工具。
- 不读取范围外 iframe 的内容。混合范围页面明确拒绝截图、键盘输入和滚轮滚动；范围内文本读取与可验证点击仍可使用。范围外网页弹窗由用户处理，内容不返回模型。
- 范围不支持 query/hash 规则或编码后的分隔符、嵌套编码。平台正常请求 API、图片等资源不被页面范围规则拦截。
- 未配置范围时 Agent 不访问页面。Chrome debugger/host 权限与 Agent 业务范围不同，本功能在工具执行层检查业务范围。

## 桌面通知

审批事务同时登记通知。插件后台每 30 秒拉取，创建桌面通知后确认回执。通知失败不重新审批。

Chrome 退出、电脑休眠或断开内网时，服务器保存待发通知，客户端恢复后补发。关闭侧栏或平台标签页不停止通知。系统免打扰、通知设置及 Chrome 权限会影响实际展示。

点击通知打开允许范围内的白名单页面；若该页面不在路径范围内，则打开设置。浏览器在通知创建与持久化之间崩溃时可能重复提醒；通知创建成功不等于你已读。

断开登录前先暂停任务。删除插件全部数据也会先暂停已连接的服务器任务；若服务器不可访问，应先恢复连接或由管理员在服务端暂停，再删除连接数据。

## 对话管理

连接平台后，Agent 获得 `get_whitelist_watch_status` 和 `set_whitelist_watch_state` 两个工具，可查询、启用和暂停任务。启用时确认一次列出平台和“已有及新增全部同意”范围的授权卡，不逐条确认申请。

可说：“查看白名单自动审批状态”“暂停自动审批”“开启白名单自动审批”。模型不能修改地址、凭据或收件人；申请数据处于不可信内容边界内。

## 后端数据与恢复

数据在原申请 JSON 目录下的 `expert_mode.sqlite3`，通常是 `pilot/expert_mode.sqlite3`。

- 首次启动在一个事务中导入原申请、白名单 JSON。原文件保持原样作为备份，此后只写 SQLite；修改旧 JSON 不再影响运行状态。
- 申请增加稳定 ID 和版本，保留原下标接口。前端提交申请 ID 和版本；已处理申请不允许覆盖。
- 申请审批、白名单、审计和通知在同一个事务提交。移除白名单将有效历史申请标记为已撤销，不会被任务重新开通。
- 启用任务记录授权管理员，每轮确认其管理员身份仍有效，失效则停用并记录错误。
- 重启按数据库任务状态与下次检查时间恢复，多进程通过数据库事务避免重复审批。
- 停止服务后备份 SQLite 和原 JSON。数据库、账号、令牌和实际申请数据不要提交到 Git。

新增管理员接口：`GET/POST /api/v1/expert-mode/watch`、`GET /api/v1/expert-mode/notifications`、`POST /api/v1/expert-mode/notifications/{id}/ack`，沿用 `user-id` 与 `x-auth-token` 会话鉴权。

## 内网运行

前后端、模型和数据全部部署在内网。管理员密码在插件登录界面填写；模型兼容接口与 API Key 在提供方设置中配置。`127.0.0.1` 指运行组件自己的机器，跨机器部署应填写实际内网地址。

本次没有新增项目依赖。插件离线 store 使用同一 lockfile；dbgpt 新存储使用 Python 标准库 SQLite。独立 Chrome for Testing 使用模拟数据验证，具体结果见交付验证记录。
